# toSub2

账号行的操作列提供“登出所有设备”按钮；勾选账号后，可使用“登出所选账号所有设备”。确认后会提交所选账号的全部设备与会话登出请求（包括当前会话），不会自动重新授权。批量操作最多并发 3 个请求，跳过正在运行或没有已保存授权的账号；成功项取消勾选，失败及跳过项保留以便重试，并显示成功、失败、跳过数量和失败原因。服务端可能需要几分钟完成登出传播，之后可能需要重新登录。

toSub2 是一个本地网页工具，通过协议请求完成 ChatGPT 登录和 Codex OAuth（授权登录），自动判断账号是否需要绑定手机号，并生成可供 sub2api 导入的 JSON（结构化数据）文件。

> 本项目不是 OpenAI 官方项目。上游登录接口随时可能变化。

![toSub2 控制台](docs/console.png)

## 工作流程

1. 通过邮箱验证码或密码登录 ChatGPT。
2. 账号启用 2FA（双重身份验证）时，自动生成并提交 TOTP（基于时间的一次性密码）。
3. 发起 Codex OAuth（授权登录）。
4. 根据服务端响应判断账号是否已经绑定手机号。
5. 未绑定手机号时进入短信验证，支持手动号码、LubanSMS（鲁班接码）、SMSBower（短信接码平台）或自定义接码 API（接口）。
6. 选择 workspace（工作区），兑换 OAuth Token（授权令牌）。
7. 生成标准 `sub2api-data` 导入文件。

## 主要功能

- 本地网页控制台，可同时管理多条登录任务。
- 默认同时运行 4 条任务，超出后自动排队；点击顶部“任务设置”可调整为 1–20 条。设置保存到服务端，刷新页面和重启服务后保留。调高立即启动排队任务，调低等待当前任务完成后按新上限调度；X1 等小规格主机建议保持默认值。
- 支持手动邮箱验证码、邮箱收码 API（接口）自动取码。
- 支持密码登录，以及密码或邮箱验证码登录后的 2FA（双重身份验证）。
- 已完成 ChatGPT 登录的账号可以单个或批量创建新的 TOTP 2FA（基于时间的一次性密码），不要求先完成手机号绑定或 Codex 授权；程序会自动生成并提交激活验证码，密钥不会写入协议日志，设置完成后可继续原授权流程。
- 账号列表显示 OAuth（授权登录）Token（授权令牌）中的 Plan type（订阅类型）；可在“PlanType 映射”中把原始值转换成自定义标签（例如 `self_serve_business_prolite` 显示为 `Business Premium`，`self_serve_business_usage_based` 显示为 `Business Usage Based`）。凭据弹窗可受控查看或更新密码、TOTP 密钥，滚动查看完整 Sub2API JSON，并支持轮换已启用的 2FA。
- 无密码账号可以单个或批量添加随机强密码，已有密码的账号会自动跳过；支持邮箱 API 自动收码或手动输入验证码，成功后会更新本地账号原始信息。账号只要已保存邮箱登录检查点即可添加密码，不要求先完成手机号绑定或 Codex 授权；添加后可继续原授权流程。
- 自动跳过已经完成手机号绑定的账号。
- 未绑定账号支持手动手机号、手动短信验证码，以及 LubanSMS、SMSBower、自定义号码池自动取号收码。
- 邮箱登录成功后立即保存 checkpoint（检查点），中断后可继续手机号流程。
- 支持单个和批量重新授权；“重新授权”优先使用已有 Refresh Token（刷新令牌），“重新登录并授权”会跳过刷新令牌和旧检查点，强制重新完成登录与授权。
- 支持分页、精确筛选、跨页多选、批量删除、停止全部、批量重新授权和批量下载。
- 可每 5 分钟巡检 Sub2API 异常账号，对上次全自动登录的任务自动重新登录并更新远端授权。
- 账号列表的“过载检测”列提供 macOS 红绿灯风格的开关与六小时迷你折线图；绿色开启、红色停止，默认停止。橙色实线统计 Sub2API 运维日志中 HTTP 503 且包含 `Our servers are currently overloaded. Please try again later.` 的报错；蓝色虚线统计请求记录中的成功与失败请求，同邮箱多条号池记录合并计数。
- 两条曲线分别按各自六小时最大值独立缩放，共用小时位置与 0 基线；线条高度用于比较各自趋势，悬浮、键盘聚焦或点击显示时段和两项原始次数，并标注“独立缩放”。过载与请求统计互相独立，某项接口失败时另一项仍正常更新，失败项保留已有历史或显示未统计，每分钟重试。
- 两项统计均在服务端每个整点更新，展示最近六个已结束的小时区间；例如 03:00 更新 02:00–03:00 的数量。开启和服务重启时补齐历史，开关和统计保存在输出目录的 `overload-monitor.json`，暂停保留已有历史。旧版历史中的请求量在首次成功同步前显示未统计。
- “任务设置 → 批量导入后的自动任务”可按 PlanType 勾选“自动开启过载检测”；账号导入并完成授权后执行，若同时选择上传或一键轮换上传，会先完成这些任务，再开启检测。规则保存到服务端并在重启后保留。
- 最终输出 sub2api 导入格式，下载文件名自动附带时间戳。

## 环境要求

- Node.js 20 或更高版本，建议使用 Node.js 22。
- Python 3.9 或更高版本；默认协议登录流程需要安装 `curl_cffi`（浏览器 TLS 指纹请求库），即使不使用代理也需要。
- macOS 使用 Keychain（钥匙串）持久保存密码、2FA 密钥和账号代理。
- Windows 使用当前用户的 DPAPI（数据保护接口）加密保存上述数据，密文位于 `%LOCALAPPDATA%\toSub2\credentials`，只能由同一个 Windows 用户解密。
- Linux 可通过 `TOSUB2_CREDENTIAL_KEY` 启用 AES-256-GCM（高级加密标准）加密文件保存密码、2FA 密钥和账号代理；该变量必须是随机 32 字节密钥的 64 位十六进制或 Base64 表示，并由部署环境通过受限环境变量或 secret（密钥管理）注入，程序不会把它写入任务目录。未配置密钥时仍可使用邮箱验证码流程，但凭据和代理不会跨服务重启持久化。

Linux 生产服务建议把凭据目录放在服务数据目录（例如 `/var/lib/tosub2/credentials`），并同时配置：

```bash
TOSUB2_LINUX_CREDENTIAL_ROOT=/var/lib/tosub2/credentials
TOSUB2_CREDENTIAL_KEY=<64 位十六进制随机密钥>
```

## 安装与启动

```bash
git clone https://github.com/poxiao33/toSub2.git
cd toSub2
npm install
python -m pip install -r requirements.txt
npm run dev
```

默认访问地址：

```text
http://127.0.0.1:4399
```

指定其他端口：

```bash
npm run dev -- --port 4400
```

允许局域网设备访问：

```bash
npm run dev -- --host 0.0.0.0
```

局域网模式没有访问认证，只应在可信网络内短时间使用。

### PM2（Node.js 进程管理器）守护运行

号池巡检依赖控制台服务持续运行。需要崩溃后自动重启或开机启动时，建议使用项目内置的 PM2 配置：

```bash
npm install -g pm2
npm run daemon:start
pm2 save
pm2 startup
```

`pm2 startup`（生成开机启动配置）会输出一条系统命令，继续执行该命令即可。默认使用 `127.0.0.1:4399` 和项目内的 `tmp/chatgpt-onboarding-console` 数据目录。

需要保留旧数据目录并开放局域网时，macOS/Linux 可以在首次启动时传入：

```bash
ONBOARDING_OUTPUT_ROOT=/path/to/existing-data ONBOARDING_HOST=0.0.0.0 npm run daemon:start
```

Windows PowerShell（命令行）使用：

```powershell
$env:ONBOARDING_OUTPUT_ROOT="C:\path\to\existing-data"
$env:ONBOARDING_HOST="0.0.0.0"
npm run daemon:start
```

常用管理命令：

```bash
npm run daemon:restart
npm run daemon:logs
npm run daemon:stop
```

PM2 只负责在进程异常退出后重启。toSub2 在正常关闭时仍会先取消巡检请求、停止登录任务并保存任务状态。

任务设置保存在数据目录的 `task-settings.json`。账号代理分配支持“全局代理”“Sub2API 均衡分配（登录前绑定）”和“动态登录 + 按 PlanType 授权”。旧 Sub2API 模式仍在登录前按出口 IP 的账号数分配并绑定；新模式先使用全局动态代理登录 ChatGPT 网页，读取当前工作空间的 PlanType 后，再按该 PlanType 绑定的 Sub2API 方案选择 Codex 授权代理。只有方案代理选择“均衡分配（toSub2）”的账号参与自动分配。没有保存过并发 UI 设置时，可以用 `TOSUB2_MAX_ACTIVE_JOBS` 指定初始值（1–20）；保存后的 UI 设置优先于环境变量。`GET /api/task-settings` 和 `POST /api/task-settings` 使用控制台令牌读取或保存设置。任务 API 的 `startedAt`、`durationMs` 可用于观察每次任务取得槽位后的耗时，排队时间不计入。任务设置还可以保存 `autoActions`（PlanType 到 `upload`、`rotate-logout-reauthorize-upload` 的数组），批量导入触发的授权完成并识别到对应 PlanType 后由服务端自动执行；没有匹配规则的 PlanType 不会自动执行其它操作。

## 账号代理和 TLS 指纹

网页顶部的“代理 IP”输入框配置账号登录使用的代理。支持以下格式：

```text
http://用户名:密码@主机:端口
socks5h://用户名:密码@主机:端口
socks5h://account-id:proxy-secret-JP-91977332-20m@proxy.example.com:1000
```

如果用户名中存在 `-sid-xxxxxxxx-t-20`，或者密码中存在 `-JP-12345678-20m` 这样的会话字段，toSub2 会为每个任务随机生成新的会话编号，并使用 `curl_cffi` 的 Chrome 浏览器 TLS 指纹真实访问 `chatgpt.com` 检测出口。未配置代理时默认直接使用 `chrome146`，不在正常任务启动前筛选指纹；如果遇到 Cloudflare（云防护平台）挑战，会优先使用本地求解器处理，只有求解失败时才启动一次共享的直连 TLS 指纹筛选作为兜底，然后用筛选出的指纹重试当前任务。通过 `--tls-profile` 或 `TOSUB2_TLS_PROFILE` 显式指定时使用指定指纹，也可以显式指定 `auto` 才启用指纹探测。如果当前 Python `curl_cffi` 或底层库不支持指定指纹，会自动降级到兼容指纹，并把实际降级结果同步给后续流程。协议请求的 User-Agent、Client Hints、OAuth 请求头以及补充账号资料时的 Sentinel 浏览器环境都会跟随最终指纹版本，不再混用固定版本或不同操作系统环境。HTTP 风控响应会更换会话，最多使用 10 个有响应的代理会话；TLS、超时等纯连接失败不占这 10 次，但连续连接失败达到 20 次也会停止，避免网络异常时无限循环。代理检测通过后，如果在邮箱登录、2FA、手机号绑定、工作区选择或 OAuth（授权登录）阶段再次遇到 403 HTML 风控页，任务会清除本次无效登录状态、换新代理会话并从当前流程起点自动重试。没有可识别会话字段的固定代理不会重复轮换，失败后直接提示用户更换代理。

代理首次检测通过后，正式登录和授权流程如果再次遇到明确的安全校验页面，会先保持当前代理出口重试最多 3 次；手机号验证码发送接口只有在 `400/409` 同时带有安全校验响应头或实际安全校验页面时才采用相同策略。连续 3 次重试后仍然触发风控，才会进入更换代理并重新授权流程。普通手机号不可用、`invalid_state` JSON 等业务错误不会触发代理重试，只提示用户更换当前手机号。

当响应包含可执行的 Cloudflare（云防护平台）挑战配置时，toSub2 会优先在当前 `curl_cffi` Session（会话）中运行父挑战和 Turnstile（人机验证）子挑战。获得 `cf_clearance` 后会使用同一代理出口、同一 TLS 指纹和同一 Cookie 会话重放原请求。只有挑战无法完成或重放后仍被拦截时，才进入上述同出口重试和随机会话编号兜底。该运行环境依赖 `jsdom`（网页环境模拟器），执行 `npm install` 时会自动安装。

Sentinel（动态安全令牌）不再使用项目内置的静态 PoW/DX 生成器。每个登录会话会实时下载 Sentinel 加载器和当前版本 SDK，在独立的 `jsdom` 父页面和 iframe（内嵌页面）中执行，并由当前 Python `curl_cffi` Session 提交 SDK 产生的请求。生成过程复用账号当前代理、Cookie、设备 ID、TLS 指纹、User-Agent 和平台语言信息；代理会话或 `sid` 更换后会销毁旧 Sentinel 运行时并重新初始化。最终按服务端要求生成 `OpenAI-Sentinel-Token`，存在 Session Observer（会话观察器）数据时同时生成 `OpenAI-Sentinel-SO-Token`。

代理 IP 和“代理失败时允许回退本地出口 IP”开关通过“保存代理配置”写入服务端运行数据目录的 `task-settings.json`（权限 `0600`），刷新页面、切换浏览器或重启服务后恢复。输入框修改后需要保存才会用于任务；多个浏览器共用服务端配置，其他页面约每 15 秒读取最新配置。该文件可能包含代理用户名和密码，应作为敏感配置保护。旧版浏览器 localStorage 中的代理不会自动覆盖服务端配置，需要手动填写并保存一次。

配置了全局代理后，新建任务、重试、重新授权，以及号池异常监测触发的自动重新登录均优先使用已保存的全局代理。页面执行任务不再提交输入框的代理值，因此空输入框不会清除账号代理。未配置全局代理时保留账号原有代理，没有账号代理时使用服务器出口 IP。账号代理仍保存在系统安全凭据存储中；代理密码不会写入 `job-meta.json`（任务元数据）或日志。

本地出口回退默认关闭：代理不可用时任务停止，不会改用服务器出口。开启后，固定代理检测失败或轮换代理达到重试上限时，本次任务允许回退服务器出口 IP 重试一次；不会删除已保存的代理，下次重新登录仍先尝试代理。密码错误、账号封禁等业务错误不会触发出口回退。

Python 辅助进程默认使用 `python3`（macOS/Linux）或 `python`/`py -3`（Windows）。如果系统有多个 Python，可以设置环境变量 `TOSUB2_PYTHON` 指定解释器路径。

### Codex 授权来源

在“任务设置 → Codex 授权方式”中选择凭据生成方式，保存后对后续开始的登录、重新登录和重新授权生效；正在运行的授权沿用启动时的方式，设置在服务重启后保留。

- **本地授权（默认）**：toSub2 生成 OAuth 链接、维护 PKCE 状态并直接兑换或刷新令牌。
- **Sub2API 授权**：复用已保存的 Sub2API 后端地址与管理员 API Key，调用 `POST /api/v1/admin/openai/generate-auth-url` 取得授权链接和 `session_id`。toSub2 完成登录及授权回调后，将 `code`、`state` 和会话 ID 交给同一后端的 `exchange-code` 接口兑换凭据；重新授权优先调用该后端的 `refresh-token` 接口。

Sub2API 模式需要后端支持上述接口。账号代理模式会在链接生成、令牌兑换和刷新时传递已绑定的 `proxy_id`；全局代理需要与 Sub2API 中可用代理的连接地址一致，否则任务显示配置错误。匹配后的全局代理在本次授权中同样固定，不自动轮换或回退直连。未配置代理时两端使用各自的直连出口；如需同一出口，请启用账号代理模式。远端刷新由 Sub2API 执行，不额外探测 toSub2 的登录代理；明确返回刷新令牌失效时，自动重新登录并继续使用 Sub2API 授权。

新方式复用现有本地凭据导出及号池更新机制，重新登录、冷却恢复和切换 IP 后仍会更新已有号池账号。授权提供方的会话与 PKCE 状态分开保存，切换方式或后端后，保留可用的登录会话并重新开始对应提供方的授权。后端接口错误会显示失败信息，未完成的授权不覆盖原凭据。

### Sub2API 账号代理与批量维护

按 PlanType 选择代理时，先在“代理 IP 配置”中保存用于网页登录的动态代理，在“Sub2API 设置”中按方案绑定 PlanType，并选择“使用账号原配置”“指定代理”“直连”或“均衡分配（toSub2）”，最后在“任务设置 → 账号代理分配”选择“动态登录 + 按 PlanType 授权”。网页登录与 Codex 授权共用已验证的 Cookie；切换授权代理时会固定该代理会话，授权链接、令牌兑换、刷新及号池同步使用同一授权代理。未识别当前工作空间或 PlanType 时停止授权并保留登录断点。未绑定方案的 PlanType 使用当前方案；“使用账号原配置”保留已有号池代理，新账号没有原代理时直连。

均衡分配按出口 IP 的账号总数选择当前最少的一侧，同一出口的多个节点合并计数，并发任务预留分配数量。已有绑定在重新登录与服务重启后保留。账号列表的“绑定 IP”列展示号池当前代理的出口 IP；尚未上传的账号展示本地授权绑定，未绑定和直连有单独标记。Sub2API 配置中的 `balanced` 是 toSub2 专用标记，写入号池前转换成实际数字代理 ID。原“Sub2API 均衡分配（登录前绑定）”模式仍可单独选择。

账号的登录、重新授权及号池凭据更新均沿用绑定代理；方案中的统一代理设置不覆盖该绑定。此模式保持代理原有会话编号，不自动轮换或回退直连。绑定节点失效时显示错误，修复代理或使用“一键切换 IP”后继续。代理凭据保存在本机安全凭据存储中，绑定 ID、冷却截止时间和同步状态保存在任务元数据中。

选中多个已授权且空闲的账号后，可以使用：

- **一键冷却**：登出全部设备，保留代理绑定。在“任务设置”中设置冷却分钟数（默认 60，范围 1–43200）；到期自动重新登录、授权并更新 Sub2API 号池凭据。服务重启后恢复截止时间，过期任务会继续执行。
- **一键切换 IP**：按当前绑定数量为账号选择不同出口 IP，登出全部设备，再通过新代理登录授权并更新号池。没有不同的可用出口时返回失败信息。

普通“重新登录并授权”、单个或批量“重新授权”成功后，也会自动更新号池凭据。登录失败时保留错误状态；授权成功但号池暂时不可用时保留待同步状态，每分钟重试同步，重启后继续，不重复登录。需要邮箱验证码或 2FA 验证时，继续使用现有的自动收码或手动输入流程。

## 批量添加格式

每行一个账号。toSub2 会根据字段特征自动识别邮箱、密码、邮件接收 API 和 2FA 密钥，字段顺序不固定。现有 `----` 格式仍完全兼容：

支持 `邮箱----密码----2FA密钥(备注)`，例如 `name@example.com----账号密码----JBSWY3DPEHPK3PXP(首批账号)`；紧跟 2FA 字段的英文或中文括号内容会保存为备注，密码中的括号仍按密码处理。重复导入时省略备注会保留原备注。账号行下方的“添加备注”或现有备注可以点击编辑，支持多行文本，最多 2000 字。本地 `remark` 与号池 `notes` 双向同步：导入或保存会更新同邮箱全部号池账号的完整备注，清空也同步；在号池修改或清空后，页面约每 15 秒同步回显并持久保存。保存失败的本地内容会保留为待同步状态，后续同步自动重试，服务重启后仍保留。编辑弹窗中的草稿不会被轮询覆盖。历史同邮箱重复账号的备注不一致时，优先采用本次发生变化的记录，再按 `updated_at` 和账号 ID 确定来源；没有变化时保留已选内容，避免来回切换。尚未进入号池的账号在上传或下载 JSON 时带上备注；多行备注请通过 JSON 下载保留，单行备注也可随原始账号文本导出。

```text
邮箱
邮箱----邮箱收码接口
邮箱----密码
邮箱----密码----2FA身份验证密钥
邮箱----密码----邮件接收API
邮箱----密码----邮件接收API----2FA身份验证密钥
邮箱----邮箱收码接口----2FA身份验证密钥
邮箱--------2FA身份验证密钥
```

示例：

```text
name@example.com
name2@example.com----https://mail.example/messages/account-token
name3@example.com----账号密码----JBSWY3DPEHPK3PXP
name4@example.com----账号密码----https://mail.example/messages/name4
name5@example.com----账号密码----https://mail.example/messages/name5----JBSWY3DPEHPK3PXP
name6@example.com----https://mail.example/messages/account-token----JBSWY3DPEHPK3PXP
name7@example.com--------JBSWY3DPEHPK3PXP
```

也可使用 `|`、Tab（制表符）、`::`、逗号、分号或连续空格分隔，例如：

```text
https://mail.example/messages/name|JBSWY3DPEHPK3PXP|账号密码|name@example.co.uk
JBSWY3DPEHPK3PXP::name+tag@example.dev::账号密码
```

解析器会先确定完整 URL（网址）、独立邮箱和 Base32（基础三十二进制）2FA 密钥，然后根据它们的边界推断分隔符，将剩余原文作为密码。因此密码内包含 `|` 等字符时也会尽量完整保留。邮箱中的合法短横线也会尽量合并回完整邮箱，不会直接把邮箱前半部分当成密码。如果一行存在多种可能的拆分方式、多个完整邮箱、URL 中的逗号或分号可能被当成字段分隔符，会明确报错并提示改用 `----`，不会静默猜测。仅有邮箱和 2FA 密钥的账号继续使用 `邮箱--------2FA密钥` 表示空密码；`邮箱----密码--------2FA密钥` 也会正确识别密码和 2FA。仅有邮箱、一个 Base32 字段和邮件 API 时，Base32 字段在 API 之前按密码保留，在 API 之后按 2FA 密钥处理；如果同时还有另一个普通字段，则 Base32 字段按 2FA。单独出现的 `http://` 或 `https://` 字段按邮件 API 处理，不支持自动区分“网址形式的密码”。邮箱支持多级域名及点、短横线、下划线、加号等常见前缀，不限制为 `.com` 后缀。邮箱是唯一字段，重复导入会更新原任务资料。

## 接码平台配置

网页顶部的“接码平台”区域可以打开统一配置页面。每个平台拥有独立配置，保存后写入当前浏览器的 localStorage（本地存储）；服务端不会持久保存 API Key（接口密钥）。

目前支持：

- LubanSMS：填写 API Key 和供应商编号。
- SMSBower：填写 API Key 后手动点击“查询价格”，再从下拉框选择国家。列表按价格从低到高显示中文国家名称、价格和库存，不显示国家缩写和国际区号。
- 自定义接码：每行填写 `+国际手机号----接码API`，一次最多 500 条。重复手机号以最后一行为准，并发任务按顺序获取未分配号码。

```text
+8613711111111----https://example.com/messages/13711111111
+8613822222222----https://example.com/messages/13822222222
```

任务到达手机号步骤后，可以使用当前选中的平台取号。SMSBower 取号时会带上用户选择时的最高价格，避免实时价格上涨后按更高价格购买。自定义接码在发送短信前会先记录接口中的旧验证码，只提交之后出现的新验证码。服务端会自动轮询短信、提取独立的 6 位数字验证码并提交。手动手机号和手动验证码流程始终保留。

新增平台时，通过统一 SmsProvider（短信平台适配器）接入，不需要复制任务轮询和状态处理代码。

API Key 只会随取号请求临时发送给本地服务，不会写入任务元数据、协议日志或导出文件。

## 直接上传到 Sub2API

任务完成后，可以在单个任务的“上传”按钮，或顶部批量操作中使用“上传到 Sub2API”，把生成的 OAuth（授权）账号直接写入指定的 Sub2API 后端号池。

首次使用时，在页面的“Sub2API”配置区域填写：

- Sub2API 后端地址，例如 `http://127.0.0.1:8080`。
- 管理员 API Key（管理员接口密钥）。请求时通过 `x-api-key` 请求头发送。
- 点击“读取配置”后读取目标号池和代理列表。目标号池支持 OpenAI 与 Composite 平台分组多选；不选择具体分组时使用后端默认号池。
- 可以统一指定代理 IP、并发数、负载因子和优先级。数字参数留空时保留每个账号原来的配置。
- 可以设置账号命名模板，例如 `chatgpt-{email}`；支持 `{email}`、`{planType}`、`{planType_disp}`（当前 PlanType 映射值）、`{accountId}` 和 `{name}`，留空时保留导入文件中的原名。模板在服务端上传前渲染，批量上传和单个上传使用同一规则。
- 配置方案内部可开启“按导入日期设置优先级”，并指定 `0–10000` 内的闭区间。每个方案独立计算，绑定该方案的所有 PlanType 共用同一套导入日期排序，不再按 PlanType 分开计算。按上海时区从早到晚分组，同日账号使用同一优先级，计算值为 `min(上限, 下限 + 日期序号)`（序号从 0 开始）。例如范围 `2–5`，两条 13 日账号都为 2，三条 14 日账号都为 3，第 4 个不同日期及之后统一为 5。导入时间优先取号池 `created_at`，缺失时取本地首次导入时间；缺少有效时间的账号保留原优先级。未绑定 PlanType 的账号沿用当前方案回退规则并参与该方案排序；开启时优先于固定优先级，保存设置、上传、状态同步及巡检会重新计算，账号增加、删除或方案绑定改变后会按新的日期集合重排。关闭后回到原优先级配置逻辑，不自动恢复历史手动值。
- 可以填写允许使用的模型，每行一个，也支持逗号分隔，例如 `gpt-5`、`gpt-5-mini`。
- 可以设置账号级 `WS mode`：`off`、`ctx_pool`、`passthrough` 或 `http_bridge`。该设置会写入 OpenAI OAuth 账号的 `extra.openai_oauth_responses_websockets_v2_mode` 及对应启用开关，并在上传和号池自动修复时保持一致。使用非 `off` 模式前，需要在 Sub2API 的 `gateway.openai_ws.mode_router_v2_enabled` 中启用新版路由。
- 可以新增多个配置方案。管理地址、管理员 API Key 和自动检测开关是全局设置；号池、代理、并发、负载因子、优先级、账号命名模板、模型白名单、Codex 指纹模式和 WS mode 由每个方案独立保存。可把任意原始 `PlanType` 绑定到方案，例如 `self_serve_business_prolite` -> Business Premium、`free` -> Free。上传时同一批账号会按绑定方案分组调用 Sub2API。
- 保存 Sub2API 配置时，如果某个已绑定方案的参数有变化，服务会立即读取号池账号列表，把改动的字段通过 `PUT /api/v1/admin/accounts/:id` 推送给 PlanType 绑定到该方案的全部账号；未改动的字段（例如单独调整过的优先级）和账号凭据不会被改写。只有保存前后都绑定了方案的 PlanType 才会推送；新绑定的 PlanType 和走未绑定回退规则的账号不会自动推送，需要时可筛选后重新上传。方案中清空的字段不会清空号池中的值。保存完成后，页面会提示更新数量和失败数量。
- 全局代理模式下，方案代理设置支持“使用账号原配置”、指定代理和“直连（无代理）”。指定代理被删除或过期时，上传、方案同步和号池巡检会优先使用代理配置中的备用代理；没有可用备用代理时会清除账号代理并直连。读取代理状态失败时会保留原代理。“动态登录 + 按 PlanType 授权”模式会按各 PlanType 方案独立选择授权代理；只有选用均衡分配的方案会自动分配 IP。“Sub2API 均衡分配（登录前绑定）”模式继续统一管理所有账号的代理。
- 配置方案中的 PlanType 绑定编辑器只显示当前选中的方案；切换方案后会切换到该方案自己的检测类型。底层仍保存为唯一的 `PlanType -> 方案` 映射；把同一个 PlanType 重新绑定到当前方案会覆盖原方案绑定。
- 方案中的空字段表示沿用导入文件或远端账号当前值，不会主动清空 Sub2API 已有配置；需要覆盖某个字段时填写明确值。
- PlanType 映射表保存在运行数据目录的 `plan-type-mapping.json`（权限 `0600`），前端启动时从服务端恢复；浏览器 localStorage 仅作为首次迁移来源。
- Sub2API 后端地址、号池、代理、WS mode、账号命名模板和管理员 API Key 会由本机服务保存到输出目录的 `sub2api-settings.json`（权限 `0600`）；浏览器只保留非敏感的界面缓存。更换浏览器或域名入口后，服务会自动恢复这份配置，管理员 Key 不会通过 API 返回到前端。

账号操作列中的工作空间按钮会通过官方 `/backend-api/wham/accounts/check` 读取该 OAuth 会话可访问的组织工作空间和个人账户。弹窗会标记当前空间、个人空间、PlanType 和不可用状态；不可用空间会根据接口错误码、HTTP 状态码和错误消息区分已移出空间、空间封禁（例如 `402`）、空间停用、无权访问或未知原因，并在标签中显示识别到的代码。点击其他空间后，服务会在任务锁内重新校验授权并原子更新现有 `sub2api-import-oauth.json` 的 `chatgpt_account_id`、`account_id`、`plan_type` 及工作空间扩展字段，不会重新上传文件、创建重复账号或改动 OAuth 令牌。任务元数据中的 `workspace_plan_type` 与账号列表同步保存，因此切换后的 PlanType 会立即回显，服务重启后也不会丢失。

账号列表的 `Plan type`、`状态`、`Sub2API 号池` 和 `号池启用` 表头提供下拉筛选，并显示可编辑的远端账号 `priority`；每个筛选下拉只展示当前账号列表实际存在的值。状态筛选覆盖排队、处理中、待邮箱码、待 2FA、2FA 未通过、待手机号、待手机码、生成中、已完成、失败、封禁、待重新授权和可继续等流程状态。2FA 验证阶段被停止或验证进程中断时，任务会标记为“2FA 未通过”，保留重新授权入口，不再笼统显示为“已取消”。在号池中时，优先级单元格的数字输入和保存按钮会更新该邮箱对应的全部 Sub2API 账号记录（范围 `0-10000`）；服务会通过已保存的管理员配置读取 Sub2API 账号状态，并按账号邮箱合并到本地任务。前端约每 15 秒重新读取一次远端状态，因此在 Sub2API 管理端直接修改优先级后，列表会在下一次同步中回显；也可以通过 `GET /api/sub2api/account-status?refresh=1` 立即刷新。`号池启用` 列的开关会更新远端账号的 `schedulable` 状态。未配置或暂时无法读取后端时，状态显示为“未同步”，不会把管理员 API Key 写入浏览器。

账号列表的“Sub2API 用量”列从已配置的 Sub2API 管理接口同步 OpenAI 账号用量，不再由 toSub2 直接请求 ChatGPT 官方 `GET /backend-api/wham/usage`。普通同步读取账号列表中的 `extra.codex_*` 快照；前端约每 15 秒刷新一次，服务端状态缓存 TTL 默认也是 15 秒。前端按 Sub2API 的紧凑样式显示 `5h`/`7d` 窗口标签、已用百分比进度条和重置倒计时，不会暴露 OAuth 令牌或原始响应。点击用量旁的同步按钮会对该账号调用 Sub2API 的 active usage 接口，并把最新结果写回当前同步状态；active 查询失败时保留最近一次快照。账号名可点击复制。

状态同步还会把仅存在于 Sub2API 的 OpenAI OAuth 账号按邮箱导入本地列表，账号下方标记“仅号池”。同邮箱已有本地账号时保留本地资料，不重复创建；API Key 账号和其他平台账号不导入。同步记录在重启后保留。如果远端返回 OAuth 令牌，会保存为本地受保护的导入文件；未返回令牌时只同步账号资料和号池状态。后续为该账号补充本地登录资料后，标签恢复显示实际登录方式。

账号列表的“账号”表头提供“全部”“密码 + 2FA”和“仅号池”筛选；“密码 + 2FA”仅匹配密码登录且已记录 2FA 密钥的本地账号。“仅号池”匹配从号池同步且尚未补充本地登录资料的账号。筛选在服务端分页前执行，支持与邮箱、PlanType、状态和号池筛选组合；切换筛选时清空勾选并返回第一页。

生产部署建议让 x1 直接运行个人 GitHub 仓库的 `feature/account-credentials-plan-2fa` 分支。应用代码位于 `/opt/tosub2/app`，运行数据和敏感凭据位于独立的 `/var/lib/tosub2`，不会随 Git 提交、拉取或更新覆盖。更新时先在本地提交并推送，再在 x1 执行 `git pull --ff-only origin feature/account-credentials-plan-2fa`，确认 `node --check src/console-server.mjs` 后执行 `systemctl restart tosub2.service`；更新前应保留 `/var/lib/tosub2` 备份。

上传选项的非敏感界面缓存仍会保存在当前浏览器的 `localStorage`（本地存储），服务端配置以设置文件为准。批量上传时，未完成的任务会自动跳过；服务端返回的各方案创建失败数量会汇总显示在控制台中。

### Sub2API 号池监控

在 Sub2API 配置中启用“每 5 分钟监控异常账号”后，本机服务会按页读取 `openai` 平台中状态为 `error` 的账号，提取邮箱并匹配本地任务。如果配置了 OpenAI 或 Composite 号池，只检查所选号池；没有选择时检查全部 OpenAI 账号。

每次巡检还会读取全部 OpenAI 账号的当前 `PlanType`，按 Sub2API 后端和账号 ID 保存上一次结果。首次看到账号只建立基线；后续发现订阅类型变化且新类型绑定了配置方案时，服务会直接调用 `PUT /api/v1/admin/accounts/:id` 更新该账号的号池、代理、并发、优先级、模型映射和账号级扩展配置，不会重新上传文件或创建重复账号。所有方案的号池会合并为巡检范围；任一方案未选择号池时按“全部 OpenAI 账号”处理。更新失败会保留旧基线，在下一次巡检重试；后端列表响应不完整时也会保留旧基线。

只有同时满足以下条件的任务才会自动重新登录并授权：

- 上次完整登录已成功，且密码、邮箱验证码、登录 2FA 均未由用户手动输入。
- 上次用到的密码和 2FA 密钥仍能从系统凭据存储读取，邮箱收码 API 仍存在。
- 任务当前没有运行、排队或执行其他操作。

手动输入绑定手机号或手机验证码不影响自动修复资格，因为账号通常只需绑定一次。自动授权成功后，toSub2 会按 Sub2API 远端账号 ID 更新凭据和当前 PlanType 绑定方案，不会通过批量创建接口新增重复账号；方案中未填写的字段保留远端值，同时恢复账号为启用调度状态。

临时网络错误、代理风控、`429` 或 Sub2API 短时不可用只会进入 5 分钟冷却。如果登录返回明确的 `account_deactivated`、`account_deleted`、`deleted or deactivated` 或同类永久停用信息，任务状态会变为“封禁”并标记为永久跳过，下次巡检不再重试。用户仍可手动点击“重新登录并授权”重新确认账号状态。

启用监控后，Sub2API 后端地址和管理员 API Key 会由本机服务保存在运行数据目录的 `sub2api-monitor.json` 中，但不会写入账号任务元数据、协议日志、状态接口或导出文件。

### OAuth 参数与会话

Codex OAuth 默认使用 `originator=codex_cli_rs`、回调地址 `http://127.0.0.1:1455/auth/callback`，以及 `openid profile email offline_access api.connectors.read api.connectors.invoke`。每次授权独立生成 PKCE 和 `state`；回调地址及 `state` 必须校验通过后才能兑换令牌。旧检查点沿用原回调地址。

可通过 `--codex-originator`、`--allowed-workspace-ids`、`--current-workspace-id`、`--codex-login-hint`、`--codex-connection` 配置登录上下文。`CODEX_INTERNAL_ORIGINATOR_OVERRIDE` 优先于命令行 originator；只有配置当前工作区才发送登录提示和 connection。

网页登录维护任务内 Cookie、来源及导航上下文；TLS 配置发生兼容性降级时同步浏览器版本信息。OAuth 令牌请求使用独立的原生 HTTP 会话和原代理配置，不发送网页 Cookie、Client Hints、Origin 或 Referer。授权码交换使用表单，刷新使用 JSON；令牌请求不自动重放，也不跟随重定向。协议参数对齐不代表本项目的 HTTP/TLS 实现与官方 Rust 客户端或真实浏览器完全相同。

验证授权与会话回归：`node test/oauth-flow.mjs`。Python 依赖版本见 `requirements.txt`；可用 `TOSUB2_PYTHON` 指向安装该版本的解释器。

## 安全说明

- `tmp/` 中包含 Cookie（登录凭证）、OAuth Token（授权令牌）和登录检查点，禁止提交或分享。
- Windows 保存的密码和 2FA 密钥由 DPAPI（数据保护接口）按当前用户加密，不会以明文写入任务目录。
- Linux 凭据文件使用 `TOSUB2_CREDENTIAL_KEY` 提供的 AES-256-GCM（高级加密标准）密钥加密，文件权限为仅服务用户可读写；生产环境应使用随机 32 字节密钥并通过 systemd（系统服务）凭据或等效 secret（密钥管理）注入。
- sub2api 导入文件包含可用的授权令牌，应当按密码文件保护。
- 凭据弹窗中的 Sub2API JSON 可能包含 access_token、refresh_token 和 id_token，仅在受保护的控制台会话中查看，不要复制到日志或聊天记录。
- 不要把 API Key、密码、2FA 密钥、验证码、Cookie 或 Token 提交到 Git 仓库。
- 网页控制台用于本机或可信局域网，不提供公网部署所需的身份认证。
- 公网反代必须在控制台前增加 Basic Auth（基础认证）、OIDC（统一登录）或 IP allowlist（IP 白名单）；`/api/bootstrap` 会返回浏览器所需的控制台令牌，不能直接暴露到公网。
- 只处理你本人持有或已获得明确授权的账号。
